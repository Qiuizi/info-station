# 筛选流水线

```
抓取 → URL 规范化去重 → 跨源事件归并（标题 bigram 相似度 ≥ 0.62，10 天窗口）
     → 规则预筛（rules.yaml：分类基础分 + T1 加分 + 关键词加减分 + 画像兴趣 + 截止临近；屏蔽词直接隐藏）
     → [有 Key] 每日谷时批量 DeepSeek JSON 打分（prompts/system.md + prompts/category/<分类>.md）
     → 最终分 → 精选 / 通知 / 简报
```

## 打分

- 模型输出 `score / summary / tags / deadline / deadline_note / relevant / should_notify / action / reason / blocked`。
- **双次独立打分**（设置里打开）：同一提示词调用两次取平均，压住单次抖动（AIHOT 的做法）。
- 提示词内容哈希写进 `items.prompt_version`，便于对比改版前后的效果。
- 没有 Key、模型关闭、熔断中或调用失败时，条目保留规则分（`scored_by = rule`）。

## 阈值（设置页可调）

| 项 | 默认 | 说明 |
| --- | --- | --- |
| 进入今日精选 | 60 | T2 信源自动 +10 |
| 弹出系统通知 | 78 | T2 自动 +10；旧文和首次导入的存量不推送；同一事件只推一次 |
| 浏览下限 | 20 | 「全部动态」隐藏更低分的噪声（搜索不受影响） |
| 旧文时长 | 48 小时 | 发现时已发布超过此时长的不推送 |

## 截止日期

规则先抽一遍（`textutil.extract_deadline`：找含“截止/报名/申报/提交/之前”的句子，取句中最后一个日期，区间取结束，缺年份按发布时间推断并处理跨年），模型再给一次；模型给出的优先，只有日期没有时刻按 23:59。

## 事件与热度

同一通知被教务处、学院、新闻网各发一次时归为一个事件，信息流只显示分最高的那条，并标注“N 个来源”。热度按事件算：48 小时内每个独立信源计一次，超过 24 小时减半。

## 每日简报

每日谷时批量打分（默认 07:30，见 README「每天一次，在 DeepSeek 谷时打分」）完成后用规则生成：今日必看（≥ 精选阈值，一事一条）、十天内截止、各分类前几条。页面上可随时“重新生成”，并可复制成 Markdown。

## 调校建议

先用一两周，对条目点 👍/👎（存进 `items.feedback`），再据此改 `prompts/` 里的价值与噪声定义、`config/rules.yaml` 的关键词，最后才整体移动阈值。
